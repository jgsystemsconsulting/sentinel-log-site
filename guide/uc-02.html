UC-2: Configure project. Actor: Admin

Main flow

  1. The administrator opens the Django admin index and the configuration models are listed: analysis types, status labels, custom fields, controlled lists, identifier schemes, risk criteria versions, colour rules, dashboard panels, and ranking rule (req-2, req-142).
  2. The administrator opens the Meridian risk criteria version; the seeded scales, categories, and matrix cells render and prior versions are retained read-only (req-17).
  3. The administrator adds a controlled-list value through the Django admin; the new value appears in the list changelist (req-38).
  4. The administrator adds a status label on the Meridian project mapped to a core status; the label appears on the project status label changelist (req-94).
  5. The administrator opens the configuration package page at /hazards/configuration/package/; the export and import panels render (req-142).
  6. The administrator submits the export form and the browser downloads a JSON package whose header format is sentinel-log-configuration and whose families include criteria_versions, controlled_lists, status_labels, custom_fields, colour_rules, and dashboard_panels (req-142).
  7. The administrator uploads the downloaded file to the import form; on a register carrying risk assessments the product refuses with the populated-system message and writes nothing, and on an empty installation it re-imports and reports Import applied with the applied families named (req-142).
  8. The administrator opens the configuration audit page at /hazards/configuration/audit/; the export session is recorded with actor and action (req-52, req-142).
